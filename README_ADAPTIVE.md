Скопировать с заменой в корень AII:

- `sampler.py`
- `also.py`
- `train_also.py`

## Какие настройки возвращены

Настройки выбраны по удачному запуску `20261023_001356` и истории от 23 октября
(`d961aaa`, `ffdcab1`). История Git не переписывалась.

| Настройка | Значение по умолчанию |
| --- | --- |
| Модель | torchvision ResNet34, CIFAR-вход, без pretrained weights |
| Первая свёртка | 3×3, stride 1, padding 1; maxpool отключён |
| Padding для RandomCrop | 4 |
| Batch size | 128 |
| Learning rate | 0.003 |
| Weight decay | 0.0001 |
| Изменение learning rate | после эпох 10 и 15, каждый раз деление на 3 |
| Число эпох | 20 |
| Seed модели / разделения | 42 / 42 |
| Разделение CIFAR-100 | 48000 train, 2000 validation; 20 validation на класс |
| Нормализация | mean=(0.5,0.5,0.5), std=(0.5,0.5,0.5) |

У `20261023_005849` в checkpoint записан `crop_padding=2` и максимум validation
63.45%. У предыдущего `20261023_001356` максимум 65.25% на эпохе 16; padding
в его checkpoint не записан, но в коде до добавления этого CLI-параметра он
был фиксирован и равнялся 4. Остальные перечисленные параметры подтверждены
конфигурацией checkpoint удачного запуска.

Эти параметры теперь одинаковы в обычном ResNet34 и новых запусках ALSO.
При этом обычный ResNet34 использует AdamW, а ALSO — свой оптимизатор с
Adam-подобными шагами и другой обработкой weight decay. Результат AdamW
65.25% не обещается для ALSO. Веса групп по-прежнему обновляются с
`pi_lr=0.001`, `pi_decay=0.01`, режимом `optimistic` и `alpha=1`.
В ALSO расписание меняет именно `optimizer.lr`, который читает его код.
В метриках записывается фактически применённый learning rate.

## Что делает семплер

1. Первые две эпохи использует весь train.
2. Перед следующей эпохой получает веса групп ALSO. Группы здесь — классы
   CIFAR-100; состав классов не меняется.
3. Сглаживает веса (`--weight-ema 0.5`), затем сравнивает с их исходным
   распределением. При весе вдвое ниже исходного оставляет примерно половину
   группы. Округление вверх до целого изображения.
4. В каждой группе сохраняет минимум: не меньше 10% и не меньше 16 изображений,
   но не больше полного размера группы.
5. Случайно выбирает это количество без повторений, перемешивает общий список.
   В каждой эпохе выбор производится заново. Пропущенные изображения остаются
   доступными для следующих эпох; это не постоянное удаление.
6. Если вес восстанавливается, количество изображений тоже восстанавливается.
   Расчёт идёт относительно исходного размера, поэтому минимум не превращается
   в необратимую ловушку. Группы с выросшим весом используют максимум все свои
   изображения, дополнительные повторы не добавляются.
7. Освободившиеся места ничем не заполняются: эпоха содержит меньше батчей.

`--weight-ema 0` отключает сглаживание и даёт прямую реакцию на текущие веса.
Это первая версия с равномерными случайными представителями внутри класса;
оценки сходства градиентов, кластеризации и контроля дефекта агрегирования
здесь пока нет. Научная новизна и ускорение с сохранением качества не доказаны.

## Небольшое повышение веса после сокращения

Надбавка действует только на вклад оставшихся изображений в обучение модели.
Внутренний нормированный вектор ALSO `pi` не перезаписывается надбавкой.
Надбавка пересчитывается из текущей доли сокращения и не накапливается от эпохи
к эпохе. Она не нормируется обратно к сумме 1.

При `--compensation 0.25`:

| Оставлено в группе | Множитель обучающего веса |
| --- | --- |
| 100% | 1.000 |
| 50% | 1.125 |
| 20% | 1.200 |
| 10% | 1.225 |

`--compensation 0` отключает надбавку. Разрешён диапазон 0–1; коэффициент 1
не означает полную компенсацию сокращения. Доля обработки группы по-прежнему
уменьшается. Надбавка не требует дополнительных проходов модели.

## Почему потери для ALSO корректируются отдельно

Уменьшение числа наблюдений группы само по себе уменьшало бы сумму её потерь.
Это запускало бы цепочку «меньше примеров — меньше вес — ещё меньше примеров».
Поэтому перед обновлением `pi` потери корректируются по соотношению исходной
и фактической частоты группы. Для модели эта поправка не применяется:
намеренное ослабление группы и экономия вычислений остаются.

Поправка устраняет перекос частот в среднем для фиксированных потерь при
случайном выборе представителей. При обучении без возвращения модель и веса
меняются между батчами; точная условная несмещённость и перенос гарантий ALSO
на этот вариант не утверждаются. Меньшее число батчей также означает меньше
обновлений `pi` за эпоху. Для отдельного эксперимента доступно
`--pi-correction none`.

## Запуски

Проверка кода без загрузки CIFAR:

```bash
python -m unittest discover -s tests -v
```

Короткая проверка настоящей модели на двух батчах CIFAR (датасет скачивается,
если его ещё нет; эта проверка не оценивает качество):

```bash
python train_also.py --smoke-test --batch-size 16
```

Обычный ResNet34 с возвращёнными настройками:

```bash
python train_resnet34.py
```

ALSO без сокращения, с теми же настройками, что у нового семплера:

```bash
python train_also.py --sampling without_replacement --epochs 20
```

Новый семплер с небольшой компенсацией:

```bash
python train_also.py --sampling adaptive --epochs 20 --compensation 0.25
```

Для оценки именно компенсации повторить адаптивный запуск с
`--compensation 0`, затем, при необходимости, с `--compensation 0.5`.
Рекомендуется повторить сравнение на нескольких одинаковых для вариантов
seed. Все варианты используют один и тот же validation split.

Для настроек старого ALSO-прогона `20261023_145021_890855_ALSO`, а не
возвращённого набора параметров ResNet34:

```bash
python train_also.py --sampling without_replacement --lr 0.001 --weight-decay 0.001 --scheduler none
```

`--no-save-model` отключает большие `model_best.pt` и `model_last.pt`, сохраняя
метрики и состояния выборки. Оба модельных checkpoint предназначены для
оценки, не для точного возобновления обучения.

## Логи и сравнение

- `config.json`: все параметры, архитектура, источники настроек.
- `metrics.csv`: обычные метрики, число примеров/батчей, сохранённая доля,
  время обучения и валидации, накопленные время и число обработанных примеров,
  худшая validation accuracy класса, learning rate.
- `group_metrics.csv`: для каждого класса исходный/активный размер, веса до и
  после эпохи, сглаженный вес, надбавка, поправка потерь, наблюдаемая train loss
  и validation accuracy.
- `pi_initial.pt`, `pi_epoch_XXX.pt`: внутренние веса ALSO, без надбавки.
- `sampler_epoch_XXX.pt`: выбранные индексы внутри train Subset и в исходном
  датасете, размеры групп и коэффициенты текущей эпохи. Только adaptive.

Validation всегда полный и не используется семплером. Train accuracy и train
loss относятся к выбранным изображениям; их нельзя напрямую приравнивать к
метрикам на полном train. Худшая accuracy класса шумная: всего 20 validation
изображений на класс.

Время `seconds` включает выборку, обучение, validation и сохранение файлов в
пределах эпохи; загрузка датасета и создание модели в него не входят.
`train_seconds` отдельно показывает время самого обучения. Расписание learning
rate привязано к эпохам: в сокращённом прогоне снижение происходит после
меньшего числа шагов. Для эксперимента без такого эффекта можно задать
`--scheduler none` обоим вариантам.

Сравнить два результата (подставить настоящие папки):

```bash
python plot_metrics.py runs/BASELINE_RUN runs/ADAPTIVE_RUN --output runs/comparison.png
```

Скрипт читает и старые CSV. Если в старом файле нет числа изображений или
групповых метрик, он их не выдумывает. Главные критерии — validation accuracy
при одинаковом времени/числе обработанных изображений и время до заданной
точности; число эпох само по себе не показывает экономию.

- Два шага настоящего ResNet34 на искусственных изображениях, CPU:
