# Гистограммы распределения обучающих данных

Замените нужный скрипт в проекте файлом из архива:
- `train_also.py`: CIFAR-100, фиксированные подгруппы внутри классов.
- `train_also_batched.py`: CIFAR-100, фиксированные случайные группы размером batch_size, смешивающие классы.

Замените также `sampler.py` файлом из архива. `also.py` используется прежний.

Аргументы запуска:

```text
--histograms 1    создавать гистограммы (по умолчанию)
--histograms 0    не создавать гистограммы
```

В списке аргументов Kaggle добавьте `"--histograms", "1",` либо `"--histograms", "0",`.
Размер выборки группы рассчитывается напрямую:
`новое количество = предыдущее количество × текущий вес ALSO / вес ALSO в начале предыдущей эпохи`.
Затем применяются минимальный порог, ограничение размером группы и округление вверх.
Во время разогрева используется вся группа, но снимок весов также обновляется.
`--compensation` сохраняется. Настройка `histograms` записывается в `config.json`.
Поля весов группы в `group_metrics.csv`: `pi_start` и `pi_end`.
Версия семплера в конфигурации — 3.

Для гистограмм нужен matplotlib (`pip install matplotlib`, если его нет).
При `--histograms 0` matplotlib не импортируется и папка `histograms` не создаётся.
Все CSV и `groups.pt` сохраняются по-прежнему; графики можно построить позже.

При включённых гистограммах после полного прогона автоматически появляются **2 PNG** в `runs/<прогон>/histograms/`:

| Файл | Содержание |
| --- | --- |
| `classes_epoch_XXX.png` | Уникальные изображения по классам CIFAR за последнюю эпоху |
| `groups_epoch_XXX.png` | Уникальные изображения по группам ALSO за последнюю эпоху |

XXX — номер последней завершённой эпохи. Синие столбцы слева — исходное число изображений обучающего набора.
Оранжевые справа — число уникальных выбранных изображений. Столбцы стоят рядом, без наложения.
Повторные выборы изображения и его аугментации не увеличивают число данных.
На графиках последней эпохи используются уникальные индексы этой эпохи (`train_unique`).
Исходный размер никогда не умножается на число эпох. Оранжевый столбец не превышает синий.

Группы представлены отдельными столбцами, классы — отдельными столбцами; это не отдельная картинка на каждый класс/группу.

Графики строятся после завершения обучения, вне замеров времени эпох. Прежние CSV-поля сохранены.
В `class_metrics.csv` и `group_metrics.csv` сохраняется `train_unique` — число разных изображений за эпоху, в том числе при `--histograms 0`.
`train_seen` остаётся числом обработок за эпоху для расчёта метрик; при adaptive/without_replacement
оно равно `train_unique`, при with_replacement может быть больше. Логика отбора и оптимизации не менялась. Smoke-test с ранним выходом после двух батчей не создаёт итоговых графиков.

Для прогона, выполненного обновлённым скриптом, можно построить графики позже, если сохранены
`groups.pt`, `class_metrics.csv` и `group_metrics.csv` с полем `train_unique`.
Старые CSV без этого поля функция отклонит: сумма обращений не подставляется вместо уникальных данных.

```python
from train_also_batched import save_distribution_plots  # либо from train_also import ...
save_distribution_plots('/kaggle/working/runs/НУЖНЫЙ_ПРОГОН')
```

Чтобы дополнительно посмотреть каждую эпоху:

```python
save_distribution_plots('/kaggle/working/runs/НУЖНЫЙ_ПРОГОН', per_epoch=True)
```

Тогда получится 2 × E PNG, то есть 40 при 20 завершённых эпохах.
Незавершённые записи после прерывания пропускаются. Повторный вызов обновляет те же файлы.

Проверено на синтетических данных: оба скрипта, все три режима семплирования, по три эпохи;
уникальные счётчики сверены с фактически полученными индексами, включая повторные выборы внутри эпохи; PNG открываются,
построение не меняет состояние генератора PyTorch. Полное обучение ResNet34 на CIFAR не запускалось.


## Сравнение ALSO и Adaptive Batching

Ноутбук `AII_ALSO_vs_Adaptive_CIFAR100_5seeds.ipynb` содержит все исходники и запускает
пять пар (seed 44–48) на CIFAR-100 и ResNet34. Оба метода используют одинаковые
фиксированные случайные группы из `train_also_batched.py`; обычный ALSO проходит весь
набор, Adaptive использует сокращённую выборку. AdamW в этом сравнении отсутствует.
По умолчанию: 20 эпох, batch 128, lr 0.003, scheduler none, compensation 0.25.
Настройки можно поменять в первой кодовой ячейке.

`run_comparison.py` запускает обучение и затем оценивает лучший по validation и последний
checkpoints на официальном test. `plot_comparison.py` строит общие графики validation/train
cross-entropy для каждого seed и среднее ± стандартное отклонение по пяти seed.
Тестовые данные не используются при выборе лучшей эпохи.

В итогах: train/validation/test accuracy, время обучения, время эпох с validation и сохранением,
время test, оставленная доля и количество обработанных примеров. Точные значения accuracy
внутри каждого запуска хранятся как доли, в итоговых сравнительных таблицах — проценты.

Проверено выполнение 10 коротких заданий через ноутбучный запускатель на искусственных
данных с маленькой тестовой моделью, выбор checkpoint, точность test, агрегирование и 12
графиков loss. Отдельно проверен выход настоящей ResNet34 на 100 классов. Полные обучения
на CIFAR-100/GPU здесь не выполнялись.
